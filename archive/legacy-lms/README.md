# 旧LMS名称変更処理の保管方針

## 対象と結論

初期版の内部識別子 `lms` と `lms_*` テーブルを、現在の
`yuyulearning` と `yuyu_learning_*` へ変更するために作られた旧処理です。
Connect-CMS Ver.1からVer.2へのデータ移行ツールではありません。

名称変更済みの実装はmain・connect-cms-v2に反映されています。
旧データの改名処理は通常配布・自動マイグレーションへ取り込みません。
参考ソースをこのディレクトリの `.php.txt` に原文のまま保存します。
作業ブランチを保管目的で残す必要はありません。

## 利用環境ごとの扱い

| 環境 | 扱い |
| --- | --- |
| 現行版の新規導入 | 現行の作成マイグレーションでyuyu_learning_*を作成。旧処理は不要 |
| yuyu_learning_*で動作中の環境 | 改名不要。今回の整理によるサーバー作業は不要 |
| lms_*が残る初期版 | 現行配布ZIPでの更新対象外。個別調査と移行処理の改修・検証が必要 |
| CMS Ver.1からVer.2へのデータ移行 | この旧処理の対象外。別の移行計画が必要 |

## 原文を実行用として配布しない理由

ソース確認で次の問題を確認しました。実DBでの実行検証はしていません。

- upで実際に改名したかを保存しないため、新規導入で改名をスキップしていてもdownがyuyu_learning_*をlms_*へ戻し得ます。
- 外部キー削除は、対象テーブルとLaravel標準名の外部キーがすべて存在する前提です。
- 旧・新テーブルの混在を十分に検出せず、テーブル改名をスキップしてもプラグイン識別子の更新へ進みます。
- 複数のDDLと登録情報更新を一括復旧する仕組みがなく、途中失敗への対処が未整備です。

`database/migrations` にコピーしたり、`.php` に戻して実行したりしないでください。
新規導入用ZIPにこの旧マイグレーションを追加する必要はありません。

## 旧環境で移行が必要になった場合

先にDB・ファイル・migrations履歴・frames/buckets/pluginsの登録状態を保存し、
旧・新テーブル、外部キー、行数、IDと参照関係を読み取りで確認します。
検証用の複製DBで、事前条件違反時の無変更停止、途中失敗からの復旧、
受講履歴と教材参照の保持を確認した専用処理を用意してから実施します。
この資料は実行手順書でも、検証済み移行ツールの提供でもありません。
